## 2. Reusable Campaigns OS improvements

- Theme auto-generator returns empty CSS on legacy token-less stylesheets. `theme inspect` found 2 tokens / 0 mappings on legacy affiliate CSS (hardcoded hex, no :root layer); the figma-sections-export extractor needs a token layer the source does not expose, so `theme generate` emits empty CSS and the operator must hand-author the brand overlay. Generalizes to any source import lacking design tokens. Suggested fix: extractor should palette-scrape (dominant/CTA color + font-family) as a fallback, or emit a pre-filled template keyed to the next-core token list. Reviewer: Nemanja (template/tooling usage). (SIMPLE-HOME-WATCH-DOGFOOD-REPORT.md F1; simple-home-watch-assembly-report.json:225; brand-theme.css header)
- Demeter starter payment-methods.html include defaults to show_paypal=true and show_klarna=true; doctor flags frontmatter.replaceFromSpecOrApi for packages/shipping but does NOT cross-check the payment-include args against CampaignSpec.available_payment_methods. Unsupported methods (PayPal/Klarna) can ship unless manually removed. Generalizes across template families (gap matrix marks payment shell Partial/P2 for limos, demeter, MV, shop). Suggested fix: doctor should cross-check payment-methods include args against available_payment_methods. Reviewers: Nemanja (template usage), Vuk (delivery — unsupported methods reaching live). (SIMPLE-HOME-WATCH-DOGFOOD-REPORT.md F3; campaign-spec available_payment_methods=['apple_pay','bankcard','google_pay']; template-family-commerce-surface-gap-matrix.md:55)
- base.html auto-emits only 5 meta tags via {% if next_url %} (next-success/accept/decline/page-type/funnel) and does NOT auto-emit next-currency, next-predictive-address, next-prevent-back-navigation; those must be listed in explicit meta_tags frontmatter, which is easy to miss. The prior dogfood (home-outage) hit the same friction, so this is reproducible across builds. Suggested fix: base.html should emit spec sdk_hints.meta_tags automatically, or the build should warn when a page's spec meta tags are missing from rendered output. Reviewer: Nemanja (template usage). (SIMPLE-HOME-WATCH-DOGFOOD-REPORT.md F5; src/simple-home-watch-v0/*.html)
- QA runner false-negative on stepper upsell-accept network detection: step assertion 'upsell accept did not call order upsell API' (upsell_request_seen: undefined) forced disposition=blocked, yet 5/5 typed-card orders (102414/102417/re-run 102419) verified server-side with the correct upsell line and $89.97 total. Characterization CONSISTENT across re-run, not flaky — a runner observation gap during the stepper accept network window, not a campaign defect. Generalizes to any stepper data-next-upsell-action='add' path. Suggested fix: confirm the upsell add via order read-back (already passing) instead of gating solely on observing the live network call, or widen/realign the network wait for the stepper accept path. Reviewer: Vuk (QA disposition/delivery). (SIMPLE-HOME-WATCH-DOGFOOD-REPORT.md F2 + Re-run characterization; assembly-report.json qa.warnings + disposition=blocked; QA portal run MPZ92LLK142U58MAIAGSIBV8SD)
